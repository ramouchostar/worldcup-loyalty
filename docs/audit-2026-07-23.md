# Audit app — 2026-07-23

Audit croisé en quatre passes (routes & liens, API, UX membre, UX admin) +
build de production. Objectif : chemins cassés / fonctionnalités
introuvables, et poids de l'expérience utilisateur.

**Verdict global** : aucune route cassée, build propre, gardes serveur
solides (middleware admin OK — vérifié, `middleware.ts:105-122` —, tous les
`/api/admin/*` sous `requireAdmin`, crons sous `CRON_SECRET`), anti
double-soumission systématique. Les vrais problèmes : **2 fuites ADR 0007
sur des routes API mortes mais vivantes**, **3 pages orphelines**, **des
navigations qui cachent les fonctionnalités les plus importantes**, et du
**legacy Coupe du Monde encore visible** côté membre.

---

## 🔴 Lot 1 — à corriger en priorité

### Fuites / gardes API
1. **`/api/pending-rewards` renvoie les coûts € des cadeaux** —
   `app/api/pending-rewards/route.ts:14` fait `select("*")` sur une table
   qui contient `solo_cost`/`community_cost`/`advancement_cost`. Surface
   membre → violation ADR 0007. Aucun appelant UI (route morte), mais
   l'endpoint répond à tout membre authentifié. → Restreindre le `select`
   ou supprimer la route.
2. **`/api/thresholds` expose `is_unlocked` sans authentification** —
   `app/api/thresholds/route.ts:4-11`. `is_unlocked` est explicitement
   « admin uniquement » (ADR 0007). Route morte elle aussi. → Supprimer.

### Fonctionnalités introuvables (la crainte n° 1 confirmée)
3. **`/r/[id]/parrainage` orpheline** — page complète, zéro lien entrant ;
   la fonctionnalité existe en doublon dans micro-rewards. → Supprimer la
   page ou la relier (une seule source).
4. **`/admin/[id]/rewards` orpheline ET obsolète** — vocabulaire Coupe du
   Monde (« Family Bucket », `score_threshold`), fait triple emploi avec
   `/admin/menu` (paliers catalogue) et `team-tiers`. Son POST de création
   n'est appelé nulle part. → Supprimer/fusionner.
5. **`/platform` sans porte d'entrée** — le super-admin doit taper l'URL.
   → Lien conditionnel (si `is_super_admin`) dans UserNav.
6. **Nav admin à l'envers** — la sidebar (`app/admin/[restaurantId]/layout.tsx:19-30`)
   n'expose ni Opportunités, ni Ventes, ni QR, ni Réglages (accessibles
   uniquement via les cartes du dashboard), mais expose 🧪 Sandbox (outil
   de dev, jargon technique, données Belchicken en dur, « Reset tous les
   scores »). → Ajouter les 4 pages, retirer/gater Sandbox sur super-admin.
7. **Bottom nav membre trompeuse** — l'onglet « 🎁 Récompenses » mène aux
   paliers collectifs (souvent 🔒) ; le vrai parcours « récupérer mon
   cadeau » (`my-rewards`) n'a AUCUNE entrée de nav (`components/member/BottomNav.tsx:6-13`).
   6 onglets = cibles trop étroites. → 5 onglets max, entrée « Mes
   cadeaux » → `my-rewards`.
8. **Erreurs avalées sur les surfaces admin à fort volume** —
   `orders/page.tsx:302-314` et `micro-rewards/page.tsx:40-49` ne testent
   pas `res.ok` : un valider/rejeter qui échoue ne dit rien, le
   restaurateur croit avoir validé. → Tester `res.ok` + bandeau d'erreur.
9. **Tables illisibles sur mobile** — `menu/page.tsx:269` et
   `sales/page.tsx:193` : `overflow-hidden` au lieu d'`overflow-x-auto`
   (le bon pattern existe dans `MenuUploadForm.tsx:111`).

### Faux positif écarté
- ~~« Les pages admin ne vérifient pas la propriété »~~ — FAUX : le
  middleware contrôle owner/legacy/super-admin pour tout
  `/admin/[restaurantId]` et redirige sinon. Défense en profondeur possible
  (re-vérifier dans le layout), mais pas de faille.

## 🟠 Lot 2 — legacy visible & incohérences produit

    taxis : dashboard, my-team, TeamManager, LeaderboardRealtime, landing.

    l'auth qu'au submit (`actions.ts:44`).
21. **Bandeau double verrou trop promis** — `rewards/page.tsx:117-145`
    (« bientôt disponible ») vs le neutre « en pause » du dashboard (ADR 0007).
22. **Tu/vous incohérents** — `rewards` admin `:83`, `pending-rewards:72`.
23. **Actions super-admin sans confirmation** — `platform/page.tsx:127-134,186-194`

## 🟡 Lot 3 — nettoyage & polish

    `/api/pending-rewards`, `/api/orders` GET, `/api/thresholds`,
    `/api/admin/rewards` POST — les pages lisent en direct (Server
    Components). Supprimer ou documenter.
25. `push/subscribe` DELETE jamais branché (désabonnement push impossible).
26. Code mort : `InstallPrompt.tsx`, `PushPrompt.tsx`, `OnboardingTour.tsx`
    (doublon d'`OnboardingFlow`).

    coûts € dans un Server Component — pas de fuite HTTP, mais fragile) ;
    `/api/orders` GET renvoie les internes anti-fraude.
28. Stat « Membres inscrits » sous-comptée (`page.tsx:27` exige `team_id
    not null` alors que l'équipe est optionnelle, ADR 0018) et pointe vers

    `pending` (`orders/page.tsx:280`).
30. Contrastes : `dashboard/page.tsx:148` (gray-500 sur sombre), `:441`
    (gray-300 sur clair).
31. Dates sans timezone explicite — `orders/page.tsx:194` (`T00:00:00`
    local) vs pattern `T00:00:00Z` + `timeZone:"UTC"` ailleurs.
32. États vides non pédagogiques (`orders:454`, `micro-rewards admin:139`).
33. Branding triple (« Boosteats » / « Belchicken » / worldcup-loyalty) :
    classe CSS `belchicken-popover`, cookie `belchicken_ref`, fallback URL

34. `inputmode` manquants sur montant/`order_number` (`submit-order:338-348`).

## ✅ Ce qui est sain (à préserver)

- 0 lien de navigation cassé sur toute l'app ; build production propre.
- Gardes : middleware admin par établissement, `requireAdmin` sur 13/13
  routes admin, `CRON_SECRET` sur les 2 crons, `vercel.json` cohérent.
- ADR 0007 respecté sur les routes vivantes (`/api/rewards` retire bien
  `cost_euros`, `/api/scores` en points purs).
- Anti double-soumission quasi systématique ; `submit-order` exemplaire
  (loading/vide/erreur/timeout) ; page admin `orders` excellente (swipe,
  batch, SLA, motifs de rejet) ; QR imprimables très pro.
- Cohérence Opportunités ↔ Broadcast (`prefill`/`sendOn`/`promoOn`/`targetType`).
